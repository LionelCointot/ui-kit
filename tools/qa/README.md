# Vérifications navigateur du kit

`npm run qa` lance toutes les suites : construction de Storybook si les sources ont changé (signature des fichiers et des configurations, suppressions comprises, rangée dans `dist/storybook.sources` ; `--rebuild` force, `--no-build` saute), suites navigateur par 3 sur un serveur partagé, tests unitaires et statiques en parallèle, puis `fidelite` et `perf` chacune seule. Un journal par suite dans `.qa-logs/` (`--logs <dossier>`), un résumé OK/KO avec la durée de chaque suite, et `.qa-last.json` (KO par suite et par id).

- `npm run qa -- --failed` : relance les suites KO ou partielles du dernier passage, limitées aux ids KO quand la suite sait filtrer (`fidelite` : `dNN` ; `motion` : id de story, boucle générale seulement ; `axe`, `axe-autres` : id de story ; `motion-final` : bloc) ; les autres sont relancées en entier. Sans `.qa-last.json` (absent ou illisible), la commande s'arrête avec un code non nul : lancez `npm run qa`. Une relance ciblée réussie marque la suite « partielle » : `--failed` ne remplace pas un passage complet, relancez `npm run qa` avant de livrer.
- `npm run qa -- --changed` : suites choisies d'après `git diff` depuis le merge-base avec `origin/main` (repli `main`) et les fichiers non suivis (`surveille` de chaque suite dans `run.mjs`, configurations comprises ; `snippets` et `controls` seulement si `.storybook/` ou une `*.stories.ts` change).
- `npm run qa -- --only motion,fidelite` : suites nommées (noms dans `tools/qa/run.mjs`).
- `--ca31-page-neuve` (avec `motion`) : ancien mode de CA-31, page neuve pour chaque « Rejouer », pour comparer avec la seconde lecture sur la même page.
- Sans le lanceur : `node tools/qa/storybook-browser.mjs motion [fragment-d-id…]` (boucle générale seule si un fragment est donné ; échec si aucune story ne correspond), `axe [fragment… | --hors-mouvement]`, `node tools/qa/motion-fidelity.mjs d10 d37`. Chaque story est chronométrée dans le journal (`TEMPS … ms`). Attentes : `tools/qa/wait.mjs`.
